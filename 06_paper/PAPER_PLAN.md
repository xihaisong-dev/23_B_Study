### 1.2 官方版式与提交约束

1. 成品顺序固定为“封面 → 摘要页 → 正文”。论文题目、摘要和关键词均置于摘要页，正文从摘要页的下一页开始。
2. 官方模板封面保留五个 Logo、赛事名称以及学校、参赛队号、三名队员姓名字段；身份信息仅允许出现在首页。除首页外出现高校、参赛人员姓名、队伍编号等身份信息会被视为违规。
3. 论文不设页眉。页码从摘要页以阿拉伯数字 `1` 开始连续编号，置于页脚中部。Word 16.0 导出的官方模板封面可见页码 `0`，而格式规范文字写明“从摘要页开始编写页码”；LaTeX 重建时以文字规则为硬约束，并在最终模板对照中把封面 `0` 的显示差异列为待总控确认项。
4. 论文题目使用三号黑体；一级标题使用四号黑体并居中；其余汉字使用小四号宋体和单倍行距。摘要一般不超过两页，无需英文译文，应覆盖建模思路、主要方法、模型、结果与结论、创新点和关键词。
5. 最终论文必须转为 PDF，问题 B 的文件名为 `B<队伍编号>.pdf`，不得加入空格、学校名或其他前后缀。平台截图显示最多上传 1 个 PDF，单个文件不大于 50 MB。
6. 最终 PDF 定稿后计算 MD5，把该 MD5 作为论文识别码提交；生成识别码后不得再改 PDF，随后上传的必须是同一字节文件，否则平台会因识别码不一致而拒绝提交。
7. 附件上传是非必要环节；若有附件，应打包为平台允许的 `zip` 或 `rar`，最多上传 1 个文件且不大于 50 MB。若无附件则跳过。官方手册没有给出附件文件名规范，不自行杜撰。
8. 2023 官方诚信材料要求遵守学术规范，并明确标注引用文献与程序来源；截至当前官方材料核验，没有找到针对生成式 AI 的专项条款。不得用后续年份政策倒推 2023 规则；仓库 `AI_USE_LOG.md` 继续作为审慎披露与人工复核记录，但不能声称它是已核验的 2023 专项官方要求。

## 2. 证据消费原则

论文不是计算来源。正式陈述按以下链路消费冻结证据：

`论文数值或图表 -> 05_results/metrics.json 或 tournament.json -> 05_results/runs/<run-id>/run_manifest.json -> 配置/代码哈希 -> 00_admin/input_manifest.json 中的输入哈希`

写作时遵守以下限制：

1. 仅消费 `00_admin/freezes/model_results.json` 覆盖且哈希一致的模型、代码、指标、图表源数据和结果报告。
2. 题面事实、自行假设、知识库启发和本文方法分别标注；未核验来源不写成官方结论。
3. `third_party_copy` 或 `synthetic` 数据不得支撑正式排名、摘要结果或提交结论。
4. 正文不出现 `02_retrieval/`、run-id、Agent 指令、内部工程路径或数值占位符。
5. 若论文表述与冻结结果冲突，只修改论文；不得为适配文字而手改冻结结果。

## 3. 论文总体结构

正式稿建议采用下列层级，最终以当届官方模板为准：

1. 摘要与关键词：最后撰写；按问题 1—5 依次给出方法、冻结结果、验证结论和主要局限。
2. 问题重述：复述 DFT 类矩阵整数分解任务、两类约束、RMSE 与硬件复杂度定义，特别说明问题 4 的目标矩阵不是 32 点 DFT 矩阵。
3. 问题分析：说明五问由“稀疏性—离散取值—联合约束—Kronecker 推广—精度约束下复杂度最小化”逐步推进。
4. 模型假设：只保留必要且可验证的假设，并逐条说明影响。
5. 符号说明：统一 `N`、`K`、`q`、`beta=1`、`A_k`、`L`、`C=qL`、Frobenius 范数和 RMSE。
6. 通用建模与算法：说明固定 `beta=1` 的 D-005 工程口径、乘积顺序、可行性判定、优化流程、复杂度计数和统一验证设计。
7. 问题 1—5 的分题模型、结果与小结。
8. 模型检验：汇总可行性、稳健性/敏感性、消融、失败候选和复现实验。
9. 模型评价与推广：区分已证实优点、适用范围、失败条件和可推广方向。
10. 参考文献、必要附录与 AI 使用披露：内容和位置依当届规则。

## 4. 五问分题结构

每问固定使用“任务与约束—候选与选择依据—算法与参数—可行性验证—冻结结果—稳健性/失败模式—本问小结”的结构，避免只罗列算法。

### 4.1 问题 1：行稀疏约束

- 对象：`N=2^t, t=1,2,3,...` 的归一化 DFT 矩阵。
- 约束：每个 `A_k` 每行至多两个非零元素；按 D-005 固定 `beta=1`。
- 指标：最小 RMSE；复杂度按题意固定 `q=16`，报告 `L` 与 `C=16L`。
- 必写验证：矩阵尺寸、逐层行非零数、乘积顺序、固定尺度口径、不同 `N` 的适用范围与失败条件。

### 4.2 问题 2：有限取值约束

- 对象：`N in {2,4,8,16,32}` 的归一化 DFT 矩阵。
- 约束：矩阵元素实部、虚部来自题面集合；固定 `q=3`、`beta=1`，不施加行稀疏约束。
- 指标：最小 RMSE、非平凡复乘次数 `L` 和 `C=3L`。
- 必写验证：每个矩阵元素的取值合法性，以及零、`±1`、`±j`、`±1±j` 不计入 `L` 的实现一致性。

### 4.3 问题 3：稀疏与有限取值联合约束

- 对象：`N in {2,4,8,16,32}` 的归一化 DFT 矩阵。
- 约束：问题 1 与问题 2 的约束同时成立；固定 `q=3`、`beta=1`。
- 指标：先判可行，再比较 RMSE、`L` 和 `C=3L`；若冻结协议规定主次序，以协议为准。
- 必写验证：两类约束逐项验证；与问题 1、2 的可比结果只能在冻结协议允许且口径一致时讨论。

### 4.4 问题 4：Kronecker 积矩阵

- 对象：`F_4 tensor F_8`，需明确其不是 32 点 DFT 矩阵。
- 约束：问题 1 与问题 2 的约束同时成立；固定 `q=3`、`beta=1`。
- 指标：最小 RMSE、`L` 和 `C=3L`。
- 必写验证：目标矩阵构造、维度、Kronecker 顺序、联合约束与复杂度计数；不得把问题 3 的 `N=32` 结果直接代替本问结果。

### 4.5 问题 5：精度约束下的复杂度优化

- 对象：`N=2^t, t=1,2,3,...` 的归一化 DFT 矩阵。
- 约束：问题 1 与问题 2 的约束同时成立，且 `RMSE <= 0.1`；按 D-005 固定 `beta=1`，联合选择 `q`、`K` 和矩阵因子。
- 目标：在满足精度阈值后按 `(C,K,RMSE)` 字典序选择；不可用仅降低 RMSE 的结果替代复杂度优化结论。若多个 `q` 同成本，不把 `q` 设为额外平局目标；`q=1` 只能写成一个成本最优选择，不能声称唯一 `q*`。
- 必写验证：精度阈值的未舍入值判定、`q/K/L/C` 联动、边界可行性、字典序比较、最小复杂度的搜索充分性与未覆盖范围。

## 5. 数值谱系占位机制

正式结果冻结前，只在本计划中定义逻辑 claim id，不向 `main.tex` 或摘要写任何占位数字。冻结后建立 `07_review/numeric_claims.json`，每一项至少包含：

| 字段 | 约定 |
| --- | --- |
| `claim_id` | 稳定逻辑标识，如 `q3.n16.winner.rmse`；标识不承载数值 |
| `paper_source` | 论文源文件相对路径 |
| `paper_locator` | LaTeX 标签、表格单元或段落锚点 |
| `result_file` | 仅指向已冻结的 `05_results/metrics.json` 或 `tournament.json` |
| `json_pointer` | 指向精确机器值的 RFC 6901 JSON Pointer |
| `run_manifest` | 对应 `05_results/runs/<run-id>/run_manifest.json` |
| `exact_value` | 从冻结 JSON 读取的未舍入值 |
| `display_value` | 论文实际展示值 |
| `rounding_rule` | 明确小数位、有效数字及舍入方式 |
| `manual_check` | 初始为 `NOT_RUN`，复核后才可置为 `PASS` |

落数流程为：校验 `model_results` 冻结哈希 → 从 JSON Pointer 读取精确值 → 生成统一数值宏/表 → 论文只引用生成值 → 回读 PDF 展示值 → 更新人工核验状态。表格、正文和摘要复用同一宏或生成源，避免多处手录。对 `RMSE <= 0.1` 的判断必须使用未舍入值。

## 6. 图表计划

- 数据图只来自 `05_results/figure_data/` 及其冻结生成记录，复制到 `06_paper/figures/` 后保留来源和哈希。
- 每问最多优先选取能支撑约束、误差—复杂度权衡或稳健性结论的图表；每张图/表必须先在正文引出，随后解释其含义与限制。
- 概念图仅在结构或算法流程明显优于文字时使用，并要求 diagram manifest；不得将装饰性示意图当作结果证据。
- 图注需说明对象、约束、指标和比较口径，不能超出冻结数据表达的结论。

## 7. 引用计划

1. 题面参考文献只作为待核验线索；正式引用前核对 DOI、题名、作者、年份和出版信息。
2. 方法、指标和验证依据必须对应 `02_retrieval/retrieval_manifest.json` 中已核验的证据；候选失败或未采用不等于可删除其证据记录。
3. 使用唯一参考文献数据库，按正文出现顺序编号，正文以方括号标示如 `[1][3]`；书籍条目和正文引用还必须给出页码，期刊给出卷期与页码，网页给出网址及访问日期。
4. 正文引用键与参考文献条目一一对应；引用程序必须注明来源。禁止虚构文献、复制优秀论文句段或引用未实际阅读的材料。
5. 编译后检查未定义引用、孤立条目、重复条目和元数据冲突；网页来源保留访问日期和权威来源说明。

## 8. 执行顺序与完成定义

1. 保持当前 practice 题面、2025 AI 代理规则、官方模板与提交要求证据，并在论文披露代理规则不等于 2023 当届规则。
2. 等待候选运行、对擂门禁及 `model_results` 机器冻结通过。
3. 依据官方模板建立最小可编译骨架，先写无结果章节。
4. 从冻结结果生成数值宏、表格和 `numeric_claims.json`，再写五问结果、检验与讨论。
5. 最后写摘要、模型评价和提交披露，并执行 `07_review/VERIFICATION_PLAN.md` 中的全部门禁。
6. 只有真实编译成功、逐页检查完成、paper freeze 无漂移且最终硬验收脚本退出码为 0，才可由有权限的集成者报告机器验收通过；人工上传与官网回执仍由队长负责。
